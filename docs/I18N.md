# YAOPLM — interface localization

Rules for every PR that changes the interface. **English is the only supported language.** The UI strings live in the `en` catalogue: `web/src/locales/en/translation.json`.

## Mandatory

1. Every user-visible string goes through i18next (`t(...)`). The call ships **in the same commit** as the string in the `en` catalogue; "I'll translate it later" does not exist.
2. Keys are English, camelCase, grouped by screen or feature: `dump.*`, `convert.*`, `jobs.*`. A core notice code is shown through `notices.<code>`; API enum values through a prefixed key (`plan.steps.<op>`, `dump.status.<status>`, etc.).
3. Plurals use the i18next suffixes for English: `_one`, `_other`. If a phrase can be built without agreeing with a number ("Confirmed: {{count}}"), build it that way: then the key has no suffixes. Forms with identical text are a sign that suffixes are not needed.
4. Placeholders `{{name}}` are identical everywhere. `count` selects the plural form in English.
5. Typography: use “quotes” and ’ (not straight `"` and `'`); an ellipsis `…`, not three dots; an em dash `—` with spaces; no double spaces and no space before punctuation. Use impersonal forms, not the first person: "Scanning the library…", not "I am scanning…".
6. Any user-facing core text is a phrase (ADR-0029): a catalogue key and parameters. Sections: `titles` (plan, operation and job titles), `errors` (errors, whole sentences), `notices` (plan notices, game warnings, device advice, skip reasons; the notice code is the last part of the key), `reasons` (reasons embedded after a colon in another phrase: lowercase and no full stop). The core renders English from the `en` catalogue (crate `yaoplm-i18n`), so a new key goes into `en` in the same commit.
7. Parameters: numbers are passed as numbers (`count` selects the plural form, a size is written `{{size, bytes}}`), names, paths, IDs and formats as text, a reason as a nested phrase. If a number cannot be agreed without plural forms, put it in parentheses or after a dash: "ul parts: {{parts}}", "({{files}})".
8. Text boundary: everything the core tells the user, and the reasons they encounter (why OPL hides a device, what is wrong with a VMC, CUE, CHD, ZSO). Technical details — a parse error position, an OS or network library message — are inserted as-is inside the English sentence (`reasons.text`, `errors.system`). Windows returns OS messages in the system language.

## Automated checks

`web/tests/unit/i18n.test.ts`, part of `pnpm -C web test` and CI:

- keys and plural forms present in the `en` catalogue, and only on keys that have plural forms;
- identical placeholders;
- duplicate keys in the JSON itself (`JSON.parse` silently keeps the last one);
- empty strings, leading and trailing spaces, double spaces, `...`, straight quotes and apostrophes, a space before punctuation;
- a phrase for every core notice code from the Rust sources (`Notice::info/warning/error`, `skip(..)`, `fn code()` in `model.rs` and `advice.rs`);
- a phrase for every core and API phrase (`Phrase::title/error/notice/reason`), and no `titles.*`, `errors.*`, `notices.*`, `reasons.*` key that the core does not use;
- for every phrase with a literal key in the Rust sources — exactly the parameters its template uses in English (with the file and line on a mismatch);
- in Rust: every warning, skip reason, device advice and parse reason renders to English without empty placeholders; a placeholder without a value is an error in a debug build, so any test that reaches such a phrase fails;
- a phrase for every enum value the interface turns into a key (the table in the test: `StepOp` → `plan.steps`, `VerifyStatus` → `dump.status`, etc.). A new such enum goes into the table.

## Manual check before PR

- Read the new strings in English on screen (an English screenshot in the PR).
- Check the terms against the glossary.
- Keep wording short and specific: what happened and what to do; no bureaucratic language.

## Known gaps

- Technical details (OS messages, network library messages, parse errors) are shown as-is — see rule 8.
- Logs written to a device before the phrase system show their titles and notices in English.
